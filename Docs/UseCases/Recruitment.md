## 1. 모집 배너 조회

### 개요

현재 기간에 이용 가능한 모집 배너와 사용 재화를 조회한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 플레이어가 로그인되어 있고 모집 설정이 배포되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 모집 배너 조회 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 현재 시각과 계정 조건에 맞는 배너 목록 및 잔여 기간을 반환한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 이용 가능한 배너가 없으면 빈 목록과 안내 정보를 반환한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 데이터 변경 없이 최신 배너가 표시된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 서버 시간을 기준으로 배너 노출과 종료를 판정해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

### 개발 담당자

- 서버: 미정
- 클라이언트: 미정
- 기획·검수: 미정

## 2. 모집 확률 조회

### 개요

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 조회할 모집 배너가 활성 상태여야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 모집 확률 조회 기능을 선택하고 필요한 정보를 입력한다.

5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 데이터 변경 없이 확률 정보가 표시된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 표시 확률 합계와 실제 추첨 로직이 동일한 설정을 사용해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

## 3. 일반 모집

### 개요

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 배너가 활성 상태이고 필요한 재화와 인벤토리 수용 조건을 충족해야 한다.

### 이벤트 흐름

#### 기본 흐름

#### 성공 시

#### 실패 시

### 기타 요구사항

- 일반 모집과 다른 확률 및 보장 정책을 독립적으로 관리해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

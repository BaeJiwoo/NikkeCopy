## 1. 계정 생성

### 개요

플레이어가 필수 계정 정보를 입력해 신규 계정과 기본 프로필을 생성한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 로그인 상태가 아니어야 한다.
- 플레이어가 로그인 상태가 아니며 서버에 연결되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 계정 생성 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 입력값과 중복 여부를 검증하고 계정, 기본 프로필 및 초기 데이터를 하나의 작업으로 생성한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 필수값 누락·형식 오류·중복 계정이면 생성을 거부하며, 초기 데이터 생성 실패 시 전체 작업을 취소한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 계정과 초기 데이터가 생성되어 로그인할 수 있다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 비밀번호를 평문 저장하지 않고 대량 생성 요청을 제한해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

### 개발 담당자

- 서버: 미정
- 클라이언트: 미정
- 기획·검수: 미정

## 2. 로그인

### 개요

플레이어의 인증 정보를 검증하고 게임 이용을 위한 로그인 상태를 생성한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 로그인 상태가 아니어야 한다.
- 등록된 정상 계정이 존재하고 클라이언트가 서버에 연결되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 로그인 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 계정 상태와 비밀번호를 검증하고 만료 시간이 있는 인증 정보를 발급한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 정보 불일치·정지 계정·중복 접속이면 정책에 따라 거부하며 통신 실패 시 로그인 상태를 생성하지 않는다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 유효한 인증 정보가 생성되고 인증 기능을 이용할 수 있다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 실패 응답으로 계정 존재 여부를 노출하지 않고 반복 실패를 제한해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

- 기획·검수: 미정

## 4. 프로필 조회

### 개요

로그인한 플레이어의 닉네임과 진행 정보를 포함한 프로필을 조회한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

보통

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 플레이어가 로그인되어 있고 프로필이 생성되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 프로필 조회 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 인증된 계정의 프로필을 조회하여 공개 가능한 정보를 클라이언트에 반환한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 프로필이 없으면 복구 또는 기본 생성 절차를 수행하고 인증이 만료되면 재로그인을 요청한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 저장 데이터 변경 없이 최신 프로필이 표시된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 민감한 계정 정보와 내부 관리 필드는 응답에서 제외해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 변경 가능 항목과 변경 주기 및 금지어 정책을 서버에서 최종 검증해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

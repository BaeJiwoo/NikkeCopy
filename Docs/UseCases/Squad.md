## 1. 스쿼드 조회

### 개요

저장된 스쿼드의 슬롯별 니케 편성과 전투력 정보를 조회한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 플레이어가 로그인되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 스쿼드 조회 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 계정의 스쿼드와 보유 니케 상태를 조회해 계산된 전투력과 함께 반환한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 저장된 니케가 유효하지 않으면 빈 슬롯으로 보정하거나 갱신을 요구한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 데이터 변경 없이 현재 스쿼드가 표시된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 전투력 계산 기준은 전투 시작 검증과 일치해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

### 개발 담당자

- 서버: 미정
- 클라이언트: 미정
- 기획·검수: 미정

## 2. 스쿼드 변경

### 개요

보유 니케를 선택하여 스쿼드의 슬롯 구성을 변경한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

높음

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 편성 가능한 보유 니케가 있고 변경이 제한된 전투 상태가 아니어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 스쿼드 변경 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 소유권·슬롯 수·중복 편성·콘텐츠 조건을 검증하고 스쿼드를 저장한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 미보유·중복·슬롯 초과·전투 진행 중이면 변경을 거부한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 검증된 편성과 계산된 전투력이 저장된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 동일 니케의 중복 편성 여부와 빈 스쿼드 허용 정책을 서버에서 검증해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

- 클라이언트: 미정
- 기획·검수: 미정

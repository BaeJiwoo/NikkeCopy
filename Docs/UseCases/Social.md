## 1. 플레이어 검색

### 개요

닉네임이나 식별 조건으로 다른 플레이어를 검색한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

보통

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 플레이어가 로그인되어 있어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 플레이어 검색 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 검색어를 검증하고 공개 가능한 플레이어 목록을 페이지 단위로 반환한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 검색어가 너무 짧거나 결과가 없으면 안내하고 차단된 계정은 결과에서 제외한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 친구 관계 데이터 변경 없이 검색 결과가 표시된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 검색 호출 빈도와 최대 결과 수를 제한해야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

### 개발 담당자

- 서버: 미정
- 클라이언트: 미정
- 기획·검수: 미정

## 2. 친구 요청

### 개요

검색한 플레이어에게 친구 관계 생성을 요청한다.

### 관련 액터

| 액터 | 역할 |
|---|---|
| 플레이어 | 기능을 요청하고 처리 결과를 확인한다. |
| 게임 클라이언트 | 입력을 검증해 요청을 전달하고 결과를 표시한다. |
| 게임 서버 | 권한과 게임 규칙을 검증하고 데이터를 처리한다. |

### 우선순위

보통

### 선행 조건

- 플레이어가 유효한 계정으로 로그인되어 있어야 한다.
- 양쪽 계정이 정상이며 아직 친구가 아니어야 한다.

### 이벤트 흐름

#### 기본 흐름

1. 플레이어가 친구 요청 기능을 선택하고 필요한 정보를 입력한다.
2. 게임 클라이언트가 입력 형식을 확인하고 서버에 요청한다.
3. 게임 서버가 인증, 소유권 및 기능별 게임 규칙을 검증한다.
4. 게임 서버가 대상과 친구 수 제한을 검증하고 대기 상태의 친구 요청을 저장한다.
5. 게임 서버가 최신 처리 결과를 반환하고 게임 클라이언트가 이를 표시한다.

#### 대안 흐름

##### A1. 요청 또는 조건 오류

1. 자기 자신·기존 친구·중복 요청·차단 관계·친구 수 초과이면 요청을 거부한다.
2. 게임 서버는 데이터 변경 없이 실패 사유와 현재 상태를 반환한다.
3. 게임 클라이언트는 수정 또는 재시도 방법을 안내한다.

##### A2. 중복 요청 또는 서버 오류

1. 동일 요청이 중복되거나 처리 도중 서버 오류가 발생한다.
2. 게임 서버는 중복 반영을 방지하고 완료 여부를 확인할 수 있는 결과를 반환한다.
3. 완료되지 않은 작업은 데이터 일관성을 유지한 상태로 취소한다.

### 후행 조건

#### 성공 시

- 수신자가 확인할 수 있는 대기 요청이 생성된다.

#### 실패 시

- 요청 전 데이터가 유지되며 부분적으로 변경된 상태가 남지 않는다.
- 정책상 필요한 실패 기록이 저장된다.

### 기타 요구사항

- 동일한 두 계정 사이에 활성 요청이 중복 생성되지 않아야 한다.
- 모든 변경 요청은 인증과 소유권을 서버에서 최종 검증해야 한다.
- 민감 정보는 응답이나 일반 로그에 노출하지 않아야 한다.

### 개발 담당자
